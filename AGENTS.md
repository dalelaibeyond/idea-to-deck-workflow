# AGENTS.md - Global Execution Protocol for Idea-to-Deck Pipeline

## System Overview
You are a specialized AI Agent operating in CLI coding environments (e.g., OpenCode, Antigravity, Codex) executing the modular 5-phase "Idea-to-Deck" pipeline. Your objective is to transform raw, unstructured inputs into deterministic, presentation-ready artifacts in `06-outputs/`.

---

## Pipeline Topology Master Map

| Phase | Core Input | Primary Output | HITL Checkpoint / Gate |
| :--- | :--- | :--- | :--- |
| **01-Idea** | `00-inputs/` | `06-outputs/info.md` | **Mandatory Grilling:** Confirm Audience, Scenario & Objective |
| **02-Outline** | `06-outputs/info.md` | `06-outputs/outline.md` | **Structural Alignment:** Confirm SCQA narrative & Slide count |
| **03-Deck-Content** | `06-outputs/outline.md` | `06-outputs/deck-content.md` | Review on-slide copy density & voiceover scripts |
| **04-Visual-Design**| `06-outputs/deck-content.md` *(content only)* + `info.md` *(style)* | `06-outputs/design.md` | Review visual palette & Archetype assignments |
| **05-Deck-Export** | `06-outputs/design.md` + `deck-content.md` | `presentation.pptx` / `presentation.html` | **Self-Healing Run:** Terminal build & verification loop |

---

## Universal Execution Rules

### 1. File Output & Storage Hygiene
* **Strict Target Directory:** All intermediate and final output files MUST be written directly to `06-outputs/`.
* **Clean Artifacts Only:** When generating or modifying files on disk, write ONLY the raw, valid markdown/code conforming to the phase schema.
* **No Explanatory Wrappers:** NEVER persist chat logs, conversational preambles (e.g., `"Here is your markdown..."`), or extra markdown fences around the complete file. The file content must begin directly with its first valid syntax line (e.g., `---` for YAML frontmatter).
* **Completeness Guarantee:** NEVER output truncation stubs (e.g., `<!-- Slides 3-10 omitted -->` or `# ... remaining slides ...`). All slides defined in the plan must be fully drafted.
* **Single-Deck Scope & Regeneration Policy:** The workspace maintains one active deck at a time in `06-outputs/`. Re-running a phase intentionally overwrites its target file. For multiple decks, archive `06-outputs/` or manage in separate branches/directories.
* **Exclusion Directories (Pipeline-Blind):** The following prefixed directories are explicitly excluded from all pipeline execution, context reading, and artifact generation:
  - `_archive/`: Cold storage for completed sessions, legacy artifacts, and documentation not required for active pipeline runs. Agent MUST NOT read, reference, or write to this directory during any phase.
  - `_samples/`: Human-curated reference samples for user onboarding. Agent MUST NOT read, reference, or write to this directory during any phase.
  - `_review/`: Evaluation and review reports maintained by humans. Agent MUST NOT read, reference, or write to this directory during any phase.

### 2. Language & Tone Directive
* **Language Adaptability:** By default, output in the **primary language of the input materials in `00-inputs/`** or the language explicitly requested by the user. If inputs are mixed or unspecified, ask the user or default to the user's prompt language.
* **Style:** Professional, concise, punchy, active-voice statements. Avoid corporate buzzword fluff and passive constructions.
* **Domain Precision:** Retain established industry, business, and technical terms without colloquial simplification.

### 3. Strict Single Source of Truth (SSoT) & Context Isolation
* Always treat artifacts in `06-outputs/` generated by earlier phases as the absolute ground truth:
  - `06-outputs/info.md` defines verified facts, assumptions, audience, scenario, and objectives.
  - `06-outputs/outline.md` defines slide count, SCQA narrative, and Action Titles.
  - `06-outputs/deck-content.md` defines on-slide copy, layout tags, and speaker scripts.
  - `06-outputs/design.md` defines visual palette, typography, Archetype registry, and slide-archetype mappings.
* NEVER hallucinate metrics, strategic goals, or factual claims that contradict or diverge from upstream artifacts.

### 4. Human-in-the-Loop (HITL) Checkpoints & Grilling
* **Phase 1 Interrogation:** If raw inputs lack essential metadata (Audience, Scenario, Objective), STOP immediately and ask targeted clarification questions before producing `info.md`.
* **Phase 2 Confirmation:** Present the SCQA narrative and slide outline summary to the user before generating full text. Alignment is treated as **structurally confirmed** when the user explicitly approves the outline, or implicitly when the user directly invokes Phase 3 (per Rule 5) without requesting structural changes. Do not reinterpret silence as approval for other scenarios.

### 5. Single-Phase Independent Execution
Each phase can be invoked independently, provided its upstream artifact already exists in `06-outputs/`.

* **Upstream Dependency Map:**
  | Phase | Required Upstream Artifact(s) |
  | :--- | :--- |
  | Phase 1 (Idea) | Files in `00-inputs/` |
  | Phase 2 (Outline) | `06-outputs/info.md` |
  | Phase 3 (Deck-Content) | `06-outputs/outline.md` (+ `info.md` as reference) |
  | Phase 4 (Visual-Design) | `06-outputs/deck-content.md` (+ `info.md` for style context) |
  | Phase 5 (Deck-Export) | `06-outputs/design.md` + `06-outputs/deck-content.md` |
* **Missing Artifact Gate:** If a phase is invoked but its required upstream artifact does not exist, the Agent MUST STOP immediately and return a standardized error message without producing any output file:
  ```
  ⛔ Phase [N] cannot start: missing prerequisite [filename] in 06-outputs/.
  Please complete Phase [N-1] first, or place the required file manually and re-invoke.
  ```
* **Selective Re-run:** Any single phase may be re-run in isolation as long as all upstream dependencies are satisfied. Re-running a phase overwrites only its own target file.
* **Version Control Discipline:** The workspace is a git repository. After each successful phase completion (verified output file on disk), commit the affected artifacts to git so Delta modifications and re-runs remain diffable and recoverable. NEVER commit `_archive/`, `_samples/`, `_review/`, or other pipeline-blind directories.

### 6. Delta Modification & Propagation Rules (P0 Safe Updates)
When a user requests precision modifications to specific slides, obey the explicit propagation chain:
* **Authoritative Source Rule:** The `Layout Tag` in `06-outputs/deck-content.md` is the SINGLE authoritative source of slide layout. The `Layout Suggestion` in `06-outputs/outline.md` is advisory (pre-decoration intent) and the Archetype mapping in `06-outputs/design.md` is derived from deck-content. Any layout change MUST be made in deck-content.md first, then propagated downstream.
* **Case A: Copy / Text / Metric Change Only:**
  - Edit the target slide in `06-outputs/deck-content.md`.
  - Directly re-run Phase 5 (export engine) to re-render.
* **Case B: Layout Tag / Structure Change:**
  - Edit the `Layout Tag` in `06-outputs/deck-content.md`.
  - **MANDATORY PROPAGATION:** Immediately update the corresponding slide's Archetype mapping in `06-outputs/design.md`. Optionally align the `Layout Suggestion` in `06-outputs/outline.md` to prevent silent drift.
  - Re-run Phase 5 to re-render.
* **Case C: Macro Narrative / Slide Addition / Deletion:**
  - Update `06-outputs/outline.md`, then regenerate Phase 3 → Phase 4 → Phase 5.
* **Case D: Metadata / Fact Change (info.md modified):**
  - Audience, scenario, core objective, or verified facts changed in `06-outputs/info.md` invalidate all downstream artifacts. Regenerate in full chain: Phase 2 → Phase 3 → Phase 4 → Phase 5 (never patch downstream files against stale info.md).

### 7. Automated Execution & Self-Healing Loop (Phase 5)
* In CLI environments with tool-execution privileges, you MUST execute the build command and verify successful artifact creation.
* **Self-Verification Workflow:**
  1. Generate `06-outputs/build_deck.py` and/or `06-outputs/marp_deck.md`.
  2. Execute build command (e.g., `python 06-outputs/build_deck.py` or Marp render command) in terminal.
  3. Inspect execution exit code and terminal output.
  4. **Dependency Auto-Installation:** If execution fails due to a missing package (e.g., `ModuleNotFoundError: No module named 'pptx'`), execute the installation command (e.g., `pip install python-pptx`) and re-run.
  5. If a code error occurs (shape collision, syntax error), analyze the traceback, fix the code in `06-outputs/`, and re-run until the presentation file (`presentation.pptx` / `presentation.html`) exists on disk with exit code 0.
